## Pipeline overview

The pipeline is built using [Nextflow](https://www.nextflow.io/) and processes data using the following steps:

- [Read QC](#read-qc) - NanoPlot statistics before and after length/quality filtering
- [Emu](#emu) - Per-sample and combined taxonomic abundance tables
- [Emu database provenance](#emu-database-provenance) - Which database was used
- [Run checks and warnings](#run-checks-and-warnings) - Per-sample summary, warnings, database fit, Emu mode decision
- [Mock-community validation](#mock-community-validation) - Expected vs observed taxa for mock samples
- [MultiQC](#multiqc) - Aggregate report describing results and QC from the whole pipeline
- [Pipeline information](#pipeline-information) - Report metrics generated during the workflow execution

### Read QC

<details markdown="1">
<summary>Output files</summary>

- `qc/nanoplot/raw/`: NanoPlot report (`<sample>_raw_NanoPlot-report.html`), statistics (`<sample>_raw_NanoStats.txt`) and plots, before filtering.
- `qc/nanoplot/filtered/`: the same after chopper filtering (`--min_read_length`, `--max_read_length`, `--min_read_qual`).

</details>

Filtered reads themselves are not published (they stay in Nextflow's `work/` directory).

### Emu

<details markdown="1">
<summary>Output files</summary>

- `emu/<sample>_rel-abundance.tsv`: per-sample Emu result. Columns: `tax_id`, `abundance` (fraction of classified reads), taxonomic ranks, `estimated counts`. Extra rows `unmapped`, `mapped_filtered`, `mapped_unclassified` give read counts that were not classified.
- `emu/emu-combined-species.tsv`, `emu/emu-combined-genus.tsv`: all samples in one table (taxa × samples), relative abundance.
- `emu/emu-combined-species-counts.tsv`, `emu/emu-combined-genus-counts.tsv`: the same with estimated read counts.

</details>

The order of sample columns in the combined tables is not guaranteed; select columns by name.

### Emu database provenance

<details markdown="1">
<summary>Output files</summary>

- `pipeline_info/emu_db_provenance.tsv`: the `--emu_db` value, sha256 and size of `species_taxid.fasta`, sha256 of `taxonomy.tsv`, number of sequences and species.

</details>

Species names and assignments depend strongly on the database. Report this file with your results.

### Run checks and warnings

<details markdown="1">
<summary>Output files</summary>

- `ont16s_report/ont16s_run_summary.tsv`: per sample: reads before/after filtering, raw median length and quality, Emu mode, classified/unassigned/organelle/excluded fractions, database fit.
- `ont16s_report/ont16s_warnings.tsv`: the Emu mode decision and every warning with value, threshold and reason.
- `qc/emu_metrics/<sample>_emu_metrics.tsv`: per-sample Emu read accounting.
- `qc/db_fit/db_fit.tsv`: best-hit identity of a read subsample against the database.
- `emu/pooled/pooled_rel-abundance.tsv`: in pooled mode, the Emu result for all samples together.

</details>

### Mock-community validation

<details markdown="1">
<summary>Output files</summary>

- `mock_validation/<sample>_mock_validation.tsv`: one row per taxon: expected taxa (detected yes/no, observed and expected abundance, name reported by Emu) and unexpected taxa (`near_neighbour` or `off_target`).
- `mock_validation/<sample>_mock_summary.tsv`: one-row summary (recall, missing taxa, unexpected abundance, false positives, L1 distance).
- `mock_validation/mock_validation_summary.tsv`: all mock samples together; also shown in the MultiQC report.

</details>

### MultiQC

<details markdown="1">
<summary>Output files</summary>

- `multiqc/`
  - `multiqc_report.html`: a standalone HTML file that can be viewed in your web browser.
  - `multiqc_data/`: directory containing parsed statistics from the different tools used in the pipeline.
  - `multiqc_plots/`: directory containing static images from the report in various formats.

</details>

[MultiQC](http://multiqc.info) is a visualization tool that generates a single HTML report summarising all samples in your project. Most of the pipeline QC results are visualised in the report and further statistics are available in the report data directory.

Results generated by MultiQC collate pipeline QC from supported tools e.g. FastQC. The pipeline has special steps which also allow the software versions to be reported in the MultiQC output for future traceability. For more information about how to use MultiQC reports, see <http://multiqc.info>.

### Pipeline information

<details markdown="1">
<summary>Output files</summary>

- `pipeline_info/`
  - Reports generated by Nextflow: `execution_report.html`, `execution_timeline.html`, `execution_trace.txt` and `pipeline_dag.dot`/`pipeline_dag.svg`.
  - Reformatted samplesheet files used as input to the pipeline: `samplesheet.valid.csv`.
  - Parameters used by the pipeline run: `params.json`.

</details>

[Nextflow](https://docs.seqera.io/platform-cloud/reports/overview) provides excellent functionality for generating various reports relevant to the running and execution of the pipeline. This will allow you to troubleshoot errors with the running of the pipeline, and also provide you with other information such as launch commands, run times and resource usage.
